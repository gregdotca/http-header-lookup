# Changelog

## 2026-10-11

- Added `ACR.md` with the project's [AI Code Rating](https://aicoderating.com/), B2b (Maintainer: Experienced, AI Share: 26–50%, Oversight: Reviewed), and its badge in `README.md`. `git blame` attributes 167 of the 341 non-blank code lines (48%) to commits written with Claude Code; docs and the vendored daisyUI and jQuery files aren't counted.
- Fixed accessibility problems on the lookup page. The textarea had no accessible name: its placeholder is just the previous submission, and the instruction text above it was a `<div>`. That text is now a `<label for="url_list">` in `services/web/project/templates/home.html`, so screen readers announce it and clicking it focuses the box. The status badges had white text that failed WCAG AA on orange (1.97:1) and red (4.00:1). Their CSS moved from an inline `<style>` in `home.html` to `services/web/project/styles/app.css`, with orange darkened to `#c2410c` (5.18:1) and red to `#dc2626` (4.83:1). Green (`#008000`, 5.14:1) is unchanged. `CLAUDE.md` notes the contrast requirement.
- Added automatic dark mode, following the visitor's system setting with no toggle or JavaScript. `services/web/project/styles/app.css` enables daisyUI's `business` theme with `--prefersdark` alongside `bumblebee`. `home.html` drops `data-theme="bumblebee"`, which locked the page to the light theme, and adds a `color-scheme` meta tag. The Lookup button is `btn-accent dark:btn-primary`, because business's accent is an orange. An unlayered rule at the end of `app.css` darkens the dark-mode primary to navy (`oklch(34% .085 251.473)`; text on the button is 8.30:1) and copies bumblebee's corner radii, so dark mode isn't nearly square. The textarea now has daisyUI's `textarea` class (with `w-full`, since the class sets its own width): Tailwind's base styles remove form control borders, so it had no visible outline in either mode. `CLAUDE.md` describes the setup.
- Changed the page to use CSS built at Docker build time instead of loading Tailwind and daisyUI from jsDelivr. The page depended on a third-party CDN at runtime, and `@tailwindcss/browser` compiled the styles in each visitor's browser. The builder stage in `services/web/Dockerfile` now downloads the Tailwind standalone CLI v4.3.3 (checked against its SHA-256 for amd64 and arm64) and compiles `services/web/project/styles/app.css` into `project/assets/app.css`, which the final stage copies in and `.gitignore` excludes. daisyUI 5.7.46 is vendored as `project/styles/daisyui-5.7.46.mjs`. The build also scans `project/__init__.py`, because the results HTML uses `font-bold`, which isn't in the template. `CLAUDE.md` describes the build.
- Fixed redirects and statuses in the lookup results (`get_url_headers` and the new `status_badge` in `services/web/project/__init__.py`). Only 301 and 302 hops were rendered, so 303, 307, and 308 redirects disappeared from the chain. Final statuses other than 200, 404, 500, and 502 (such as 403 or 503) got a `badge-yellow` class that has no CSS, so they showed up unstyled. Every followed redirect now shows its code and destination, and final statuses are coloured by class: 2xx green, 3xx orange, and 4xx and 5xx red.
- Fixed a request without a `url_list` field calling `exit()`, which raised `SystemExit` and stopped the gunicorn worker. It now shows the existing error message on the page.
- Fixed bare IP addresses and hosts like `localhost` never showing results. Grouping combined tldextract's `domain` and `suffix`, which gave names like `8.8.8.8.` that matched no URL. URLs are now grouped by `get_base_domain` (tldextract's `top_domain_under_public_suffix`, falling back to the host), which also stops a URL appearing under a second domain because that domain is in its path. Bare IPs are no longer expanded with a `www.` prefix, and bare IPv6 addresses get the brackets a URL needs. Entries that can't be parsed as URLs (such as an unclosed `[`) still get a lookup and don't break the rest of the results. `CLAUDE.md` describes the new flow.
- Updated the dependencies, which had known security fixes in newer releases: Python 3.9.21 (out of security support since October 2025) to 3.14.8 in `services/web/Dockerfile`, and in `services/web/requirements.txt` gunicorn 20.1.0 to 26.2.0 (request smuggling fixes), requests 2.31.0 to 2.34.2, Flask 2.3.0 to 3.1.3, Werkzeug 2.3.0 to 3.1.9, and tldextract 5.1.1 to 5.3.2. urllib3 is now pinned (2.8.0), because the public-address check hooks into its connection code and a new release should be tested first. The lint step uses flake8 7.4.1, since 3.9.1 doesn't support current Python.
- Added `--no-control-socket` to the gunicorn command in `docker-compose.yml`. gunicorn 25.1 added a control socket for its `gunicornc` tool, which the app doesn't use, and it logged a permission error trying to create it in `/home/app`.
- Changed the Dockerfile to give the `app` user ownership of its home directory, not just the project directory. tldextract couldn't write its cache to `/home/app/.cache`, so it downloaded the public suffix list again on every start.
- Blocked lookups of private, loopback, link-local, and other non-public addresses in `services/web/project/__init__.py` (server-side request forgery, SSRF). The app fetched any URL it was given, so anyone using the public demo could make the server probe `localhost`, the Docker network, or cloud metadata endpoints such as `169.254.169.254`, directly or through a redirect or a hostname that resolves to a private address. urllib3's connection function is now replaced with one that resolves the host once, refuses non-public addresses, and connects to the checked IP, so redirects and DNS rebinding can't get around it. Lookups also ignore proxy settings from the environment (`HTTP_PROXY` and similar variables), because a proxy would connect to the target itself and only the proxy's address would be checked. Blocked lookups show a "BLOCKED: NOT A PUBLIC ADDRESS" badge. `CLAUDE.md` describes the hook, and now also says that values added to the results HTML must be escaped.
- Fixed a cross-site scripting (XSS) hole in `services/web/project/__init__.py`. The results are built as raw HTML and rendered with `|safe`, but the entered URLs, the base domains, and the `Location` headers and reason phrases sent back by the sites being looked up were inserted unescaped. A site could redirect with a `Location` header containing a `<script>` tag, and it would run in the browser of anyone who looked that site up. These values now go through `html.escape`.
- Updated the Usage text in `README.md` to say the app shows HTTP status codes and redirects, since it doesn't display response header values.
- Added `CLAUDE.md` with run and lint commands, the local dev/prod environment swap, and an overview of how a lookup request is processed, so Claude Code can work in the repo without rediscovering them.
- Updated the copyright notices in `LICENSE` and `README.md` from `2024` to `2024-2026` and added the contact email, to match the standard notice format.
- Fixed the install URL in `README.md` from `https://` to `http://`. Gunicorn serves plain HTTP on port 8092 with no TLS, so the `https://` link failed with a connection error.
- Added this changelog.
